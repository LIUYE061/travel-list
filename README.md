# 出行清单 · Travel List

出差 / 旅游 / 回家 / 露营前，再也不用凭记忆想"我是不是漏了什么"。
选好目的和天数，自动生成分类打包清单，逐项勾选，顶部实时显示打包进度。

**在线体验（GitHub Pages，点开即用，无需安装）：**
👉 https://LIUYE061.github.io/travel-list/

> 同一份页面的中文文件名入口：https://LIUYE061.github.io/travel-list/%E5%87%BA%E8%A1%8C%E6%B8%85%E5%8D%95MVP.html

手机上想"像个 App 一样"用（桌面图标 + 全屏无地址栏）？见下面[在手机上使用](#在手机上使用)。

## 这是什么

一个**单文件、零依赖**的 MVP 网页，用来验证"减少漏带焦虑"这个假设值不值得做下去。
没有账号、没有后端、没有埋点 —— 数据全在你自己浏览器的 localStorage 里。

手机 / 电脑直接打开链接即可使用。建议用链接访问而不是下载后双击打开 `file://`：
`file://` 下个别浏览器（Safari、部分国产浏览器内核）会禁用 localStorage，页面底部会如实提示。

## 在手机上使用

### 方式一：装成主屏幕 App（推荐，需 HTTPS）

用手机浏览器打开 https://LIUYE061.github.io/travel-list/ ：

| 系统 | 操作 | 效果 |
|------|------|------|
| iPhone（Safari） | 分享 → **添加到主屏幕** | 桌面出现行李箱图标，点开是全屏、无地址栏 |
| Android（Chrome / Edge） | 菜单 ⋮ → **添加到主屏幕** 或 **安装应用** | 同上，并可作为独立应用出现在应用列表 |

已配 `manifest.json`（`display: standalone`、192/512/maskable 三套图标、`theme_color`）
以及 iOS 侧的 `apple-touch-icon` + `apple-mobile-web-app-capable`，两端都能拿到独立图标与全屏外壳。
按你的选择**没有引入 service worker**，所以不做离线缓存 —— 代价是改版后刷新即生效，不会有旧缓存赖着不走。

> **iOS 的关键差异**：从主屏幕图标启动的网页 App 与 Safari 标签页是**两个独立存储容器**。
> 在 Safari 里勾到一半的清单，点主屏幕图标进去是空的（反之亦然）。首次使用就固定选一种入口。
> Android 上已安装应用与浏览器同源共享，不受影响。

### 方式二：局域网直连（不依赖外网，适合自己立刻在真机上验证）

`github.io` 在国内网络下经常被连接重置。手机连**同一个 WiFi**，在本机项目目录执行：

```powershell
python -m http.server 8000 --bind 0.0.0.0
```

手机浏览器打开 `http://<本机局域网IP>:8000/`（IP 看 `ipconfig` 里 **WLAN** 那条，
别用 192.168.56.1 / 176.1 / 211.1 这类 VirtualBox、VMware 仅主机网卡地址）。

两个现实限制：

- 这是 `http://` 非安全上下文，**Android Chrome 不会弹"安装应用"提示**（iOS 仍可添加到主屏幕）。
  想要真正的 App 外壳，还是得走 HTTPS 的 Pages 地址。
- 公司 / 校园 WiFi 常开 **AP 隔离**（设备之间不通），此时手机就是连不上，属网络策略而非页面问题 ——
  改用手机开热点、电脑连热点即可绕过。

三种入口（`file://`、Pages HTTPS、局域网 http）是三个不同的存储域，清单与模板互不相通。

## 已实现

- **5 类出行场景**：出差 / 旅游 / 回家 / 露营 / 短途出行
- **天数换算**：数量随天数自动变化（5 天 → 换洗衣物 ×3、内衣裤 ×5）；不过夜不出现在泳衣、电脑电源线这类条目
- **六大分类清单**：证件 / 电子 / 衣物 / 洗漱 / 药品 / 其他
- **逐项勾选** + 分类级"全部勾上 / 全部取消"
- **打包进度**：吸顶栏百分比 + 进度条 + "还剩 X 件"，100% 时提示出发前复核
- **增删物品**：自定义项带标记；删除后 5 秒内可撤销，连删可逐件撤销
- **本地持久化**：刷新、关页面不丢数据，重开直接回到上次的清单
- **个人模板**：把调好的物品集存给某个场景，下次选同场景自动套用（只记物品、数量按天数重算）

刻意不做的功能（出行方式、返程检查、AI 生成清单、云同步、分享…）见 `减法思维-出行清单.md`。

## 文件说明

| 文件 | 说明 |
|------|------|
| `出行清单MVP.html` | **交付物源文件**，单文件零依赖，双击即可打开；不含任何 PWA 引用 |
| `index.html` | **部署入口，由脚本生成**（= 源文件 + PWA 头部注入），不要手改 |
| `build_index.py` | 生成 `index.html`；改完源文件跑一次 |
| `manifest.json` | PWA 清单：`display: standalone` + 图标 + 主题色。路径全用相对 `./`，Pages 子路径与局域网根路径都能解析 |
| `icons/` | 生成的 PNG 图标：`icon-192` `icon-512` `maskable-512` `apple-touch-icon` `favicon-32` |
| `make_icons.py` | 重新生成图标（渐变底 + 行李箱，纯几何绘制，不依赖 emoji 字体） |
| `出行清单.md` | 需求与功能优先级（P0 / P1）定义 |
| `减法思维-出行清单.md` | 功能取舍过程，含"不做清单" |
| `灵魂三问--学生.md` `灵魂三问-上班族.md` | 两类目标用户的灵魂三问分析 |
| `MVP使用说明.md` | 运行方式、数据结构、localStorage key、功能边界与决策记录 |

改完 `出行清单MVP.html` 后，重新生成部署入口：

```powershell
python build_index.py
```

脚本是幂等的（同一源文件重复生成字节一致），并且带两道护栏：源文件里一旦发现 PWA 标记就报错中止，
确保"单文件零依赖"这个卖点不被污染；找不到唯一 viewport 锚点时同样中止，不会静默注错位置。

## 技术要点

- 纯 HTML + CSS + 原生 JS。**源文件** `出行清单MVP.html` 单文件、零外部请求，双击即用；
  只有部署入口 `index.html` 会多引用 `manifest.json` 与 `icons/`（共 5 个 PNG），
  页面逻辑本身仍然没有任何构建步骤与第三方依赖
- 无 service worker：不做离线缓存，因此改版后刷新即生效，不会出现"装了旧版本赖着不走"
- localStorage key：`eatwhat.travel-list.v2`；首次打开会自动从旧的 `v1` 迁移一次并提示
- 物品名支持 `{c}` / `{u}` 占位符（如 `内衣裤 ×{u}`），生成时按本次天数解析 —— 这是"模板只记物品、数量随天数重算"的实现基础
- 自定义物品按字面文本渲染，不做占位符替换；所有用户输入走文本节点，不拼接进 HTML

## 数据与隐私

所有数据只存在你本机浏览器里，站点不收集、不上传任何东西。
换设备、换浏览器、或从 `file://` 换成 `http://` 访问，数据都不互通（MVP 不做同步，属预期）。
想清空：清单页「删除清单」（模板保留），或「清除模板」，或控制台执行
`localStorage.removeItem('eatwhat.travel-list.v2')`。
