# 出行清单 · Travel List

出差 / 旅游 / 回家 / 露营前，再也不用凭记忆想"我是不是漏了什么"。
选好目的和天数，自动生成分类打包清单，逐项勾选，顶部实时显示打包进度。

**在线体验（GitHub Pages，点开即用，无需安装）：**
👉 https://LIUYE061.github.io/travel-list/

> 同一份页面的中文文件名入口：https://LIUYE061.github.io/travel-list/%E5%87%BA%E8%A1%8C%E6%B8%85%E5%8D%95MVP.html

> 安装说明直达入口：https://LIUYE061.github.io/travel-list/?install=1

手机上想"像个 App 一样"用（桌面图标 + 全屏无地址栏）？见下面[在手机上使用](#在手机上使用)。

## 这是什么

一个**单文件、零依赖**的 MVP 网页，用来验证"减少漏带焦虑"这个假设值不值得做下去。
没有账号、没有后端、没有埋点 —— 数据全在你自己浏览器的 localStorage 里。

手机 / 电脑直接打开链接即可使用。建议用链接访问而不是下载后双击打开 `file://`：
`file://` 下个别浏览器（Safari、部分国产浏览器内核）会禁用 localStorage，页面底部会如实提示。

## 在手机上使用

### 方式一：添加到主屏幕 / 桌面（**页面提供全浏览器安装引导**）

用手机或电脑上的任意现代浏览器打开 https://liuye061.github.io/travel-list/ ，页面顶部都有“安装”入口。
支持系统安装 API 的浏览器会直接弹出“安装到手机 / 电脑”；其他浏览器会显示当前浏览器的菜单路径，
并提供“复制安装网址”作为兜底。应用内置浏览器则先引导转到系统浏览器。

各浏览器的**移动端独立 App 能力**仍有差异：
（本表只谈手机；桌面端另说 —— Windows/macOS 上的 Edge、Brave 装出来是真独立应用，
有独立窗口和任务栏入口，与 Android 上的表现相反）：

| 移动端浏览器 / 环境 | 能否装成独立 App | 说明 |
|---------------|------------------|------|
| iOS Safari | ✅ | 分享 → **添加到主屏幕**，全屏无地址栏 |
| Android Chrome（有 GMS） | ✅ 真 WebAPK | 菜单 ⋮ → **安装应用**；无 GMS 的机器会退化成快捷方式 |
| Android Samsung Internet | ✅ 真 WebAPK | |
| Android Edge / Firefox / Brave / Opera | ⚠️ 仅快捷方式 | 图标带浏览器角标，点开仍在浏览器里 |
| **Via、X浏览器** | ❌ | 走系统 WebView，厂商未实现安装入口，菜单里**根本没有这一项** |
| 夸克 / UC / QQ / 百度 | ❌ 基本不支持 | 最多存成普通书签快捷方式 |
| **微信 / 钉钉 / 企业微信内打开** | ❌ 完全不支持 | 内置 WebView 不暴露安装能力 |

所以网页能保证的是“**每一款现代浏览器都有安装或快捷入口的明确操作路径**”，不能保证每款内置浏览器都给网页
开放系统安装接口。本项目的交付标准仍是：页面在任何现代浏览器里都能正常打开、勾选、存数据。

好消息是页面本身兼容性很宽，但**门槛不是 `env(safe-area-inset)`** —— 实测扫描后真正的天花板
是 **flex 容器的 `gap`（16 处）**：

| 维度 | 结论 |
|------|------|
| JS | **纯 ES5**：无箭头函数、无 `const`/`let`、无模板串、无展开、无可选链、无 `class` |
| CSS 最高门槛 | flex `gap` → **Chromium 84 / Safari 14.1（iOS 14.5）**；`overflow-wrap:anywhere` → **Safari 15.4** |
| 综合 | **完整渲染需 Chromium 84+ / iOS Safari 15.4+** |

低于该版本的退化是"**能用但变形**"，不是白屏：flex `gap` 失效会让天数快捷档、步进器、
操作按钮组**互相贴在一起**；Safari 低于 15.4 时长物品名不再断行。

> 这条结论此前被写成"约 Chromium 69+"，是错的：当时的扫描脚本把 `gap` 的正则写成行首锚定
> `^\s*gap\s*:`，而代码里 16 处 `gap:` 全在行中间，于是全部漏报。现已给每个探针加了
> "正则计数 vs 朴素子串计数"的交叉校验，两者不一致就直接报错退出，防止再次静默漏报。

已配 `manifest.json`（`display: standalone`、192/512/maskable 三套图标、`theme_color`）
以及 iOS 侧的 `apple-touch-icon` + `apple-mobile-web-app-capable`。页面顶部有“安装”入口，会区分 iOS、Android、桌面浏览器以及微信、QQ、钉钉等内置浏览器；支持原生安装的浏览器显示“一键安装”，其余浏览器显示当前菜单路径和“复制安装网址”兜底。
`sw.js` 提供应用外壳离线缓存：首次联网打开后，断网或 GitHub Pages 暂时不可达时仍可从主屏启动。页面导航采用网络优先策略，在线时不牺牲更新及时性。

> **iOS 的关键差异**：从主屏幕图标启动的网页 App 与 Safari 标签页是**两个独立存储容器**。
> 在 Safari 里勾到一半的清单，点主屏幕图标进去是空的（反之亦然）。首次使用请固定选一种入口。
> Android 上已安装应用与浏览器同源共享，不受影响。

### 关于深色模式：页面已显式声明"只支持亮色"

源文件里有 `<meta name="color-scheme" content="light only">` 与 CSS `color-scheme: light only`。
这行声明的作用是**拒绝浏览器的算法式深色改写**：本应用是纯亮色配色（没有 `prefers-color-scheme`
暗色变体），若不声明，Chromium/WebView 的"夜间模式"会自行把 `#f4f6fb` 改写成黑底、把文字翻白，
而渐变和彩色按钮不受影响 —— 结果是配色被改得半明半暗、并非设计意图。

已用 `--force-dark-mode --enable-features=WebContentsForceDark` 做过 A/B 实测。
数字来自**全图颜色普查**（取占比最高的主色），不是挑几个采样点看：

| 变体 | 页面底色 | 卡片底色 |
|------|----------|----------|
| 无任何声明 | `(32,34,38)` 21.7% | `(18,18,18)` 46.3% —— 被改写 |
| `color-scheme: light`（**不带 only**） | `(32,34,38)` | `(18,18,18)` —— **照样被改写** |
| `color-scheme: light only`（现状） | `(244,246,251)` 21.7% | `(255,255,255)` 46.4% —— 精确等于设计色 |

三点值得注意：`only` 是关键，去掉它修复就失效；`<meta>` 与 CSS 任一单独存在都生效，双写是为兼容旧内核；
两种状态下各区域像素数完全相同（109225 / 18452），说明**版式一字未动，只有配色被改写** —— 这才是干净的 A/B。

注意个别浏览器若用注入 CSS 的土办法实现夜间模式，可能仍会无视该声明 —— 那需要用户在浏览器内关闭夜间模式。

### 方式二：局域网直连（不依赖外网，适合自己立刻在真机上验证）

`github.io` 在国内网络下经常被连接重置。手机连**同一个 WiFi**，在本机项目目录执行：

```powershell
python -m http.server 8000 --bind 0.0.0.0
```

手机浏览器打开 `http://<本机局域网IP>:8000/`（IP 看 `ipconfig` 里 **WLAN** 那条，
别用 192.168.56.1 / 176.1 / 211.1 这类 VirtualBox、VMware 仅主机网卡地址）。

在 cmd 里想边开服务边留着终端用 `start /b`，**别再叠 `timeout` 或 `<nul`** ——
`http.server` 的 stdin 一旦被重定向会立刻打出
`ERROR: Input redirection is not supported` 然后自杀：

```bat
start /b python -m http.server 8000 --bind 0.0.0.0
```

要停服务用 `taskkill /PID <pid> /F`，PID 从 `netstat -ano | findstr :8000` 拿。

两个现实限制：

- 这是 `http://` 非安全上下文，**Android Chrome 不会弹"安装应用"提示**（iOS 仍可添加到主屏幕）。
  想要真正的 App 外壳，还是得走 HTTPS 的 Pages 地址。
- 公司 / 校园 WiFi 常开 **AP 隔离**（设备之间不通），此时手机就是连不上，属网络策略而非页面问题 ——
  改用手机开热点、电脑连热点即可绕过。

三种入口（`file://`、Pages HTTPS、局域网 http）是三个不同的存储域，清单与模板互不相通。

## 已实现

- **5 类出行场景**：出差 / 旅游 / 回家 / 露营 / 短途出行
- **天数换算**：数量随天数自动变化（5 天 → 换洗衣物 ×3、内衣裤 ×5）；不过夜不出现在泳衣、电脑电源线这类条目
- **六大分类清单**：证件 / 电子 / 衣物 / 洗漱 / 药品 / 其他
- **逐项勾选** + 分类级"全部勾上 / 全部取消"
- **打包进度**：吸顶栏百分比 + 进度条 + "还剩 X 件"，100% 时提示出发前复核
- **增删物品**：自定义项带标记；删除后 5 秒内可撤销，连删可逐件撤销
- **本地持久化**：刷新、关页面不丢数据，重开直接回到上次的清单
- **个人模板**：把调好的物品集存给某个场景，下次选同场景自动套用（只记物品、数量按天数重算）

刻意不做的功能（出行方式、返程检查、AI 生成清单、云同步、分享…）见 `减法思维-出行清单.md`。

改完 `出行清单MVP.html` 后，重新生成部署入口：

```powershell
python build_index.py
```

脚本是幂等的（同一源文件重复生成字节一致），并且带两道护栏：源文件里一旦发现 PWA 标记就报错中止，
确保"单文件零依赖"这个卖点不被污染；找不到唯一 viewport 锚点时同样中止，不会静默注错位置。

## 技术要点

- 纯 HTML + CSS + 原生 JS。**源文件** `出行清单MVP.html` 单文件、零外部请求，双击即用；
  只有部署入口 `index.html` 会多引用 `manifest.json`、`webclip.css/js`、`sw.js` 与多尺寸图标，
  页面逻辑本身仍然没有任何构建步骤与第三方依赖
- `sw.js` 采用网络优先的页面导航与缓存优先的静态资源策略；修改部署层或图标后需要提升 `CACHE_NAME`，避免旧缓存保留
- localStorage key：`eatwhat.travel-list.v2`；首次打开会自动从旧的 `v1` 迁移一次并提示
- 物品名支持 `{c}` / `{u}` 占位符（如 `内衣裤 ×{u}`），生成时按本次天数解析 —— 这是"模板只记物品、数量随天数重算"的实现基础
- 自定义物品按字面文本渲染，不做占位符替换；所有用户输入走文本节点，不拼接进 HTML

## 数据与隐私

所有数据只存在你本机浏览器里，站点不收集、不上传任何东西。
换设备、换浏览器、或从 `file://` 换成 `http://` 访问，数据都不互通（MVP 不做同步，属预期）。
想清空：清单页「删除清单」（模板保留），或「清除模板」，或控制台执行
`localStorage.removeItem('eatwhat.travel-list.v2')`。
